
## AREA 3 — LEAKAGE / CONTAMINATION

### 3.1 — BLOCKER · `results/phase2_kg_probe/medqa_n200.json` (`per_question[*].question_id = "test_*"`)
The Phase 2 KG probe was run on the MedQA **test** split (200 questions, seed 42).
Every Phase 2 design decision was then made by reading test-split outputs:
- ADR-015's `max_triples_per_question = 40` cap (motivated by observing test
  question `test_00001`);
- ADR-016's relevance heuristic and the novelty top-k correction;
- ADR-017's category heuristic (tuned by inspecting `test_00006`);
- ADR-018's adopt/keep-off decision for `kg_rerank`, judged on
  `overall_novel_and_relevant_rate` measured on those same 200 test questions.

Phase 7 (`docs/02_ROADMAP.md`, `docs/03_DATASETS.md`) evaluates on a
500-question seeded subset of the **same** MedQA test split
(`docs/04_EVALUATION.md:252`). `load_question_sample` uses
`random.Random(42).sample(...)` over the same file, so the 200 and the 500
overlap (~79 shared questions in expectation). A parameter (`kg_rerank` on/off,
the 40-cap, the category buckets) was chosen by looking at a quantity it will
later be judged on.
**Fix:** re-run `scripts/kg_probe.py` and `scripts/kg_rerank_ablation.py` on a
MedQA **train** slice, re-derive the ADR-015/016/017/018 decisions from it, and
add a sentence to `docs/00_RESEARCH_SPEC.md` §7 disclosing that the Phase 2
probe originally ran on test.

### 3.2 — BLOCKER · `scripts/run_baselines.py:84-100`
```python
def contamination_assertion(dataset: str) -> dict:
    if dataset == "medqa":
        return {"checked": True, "applies": False, "note": ...}
```
This executes no check — it is a literal dict. `"contamination_assertion":
{"checked": true, "applies": false, ...}` is nonetheless written into all eight
`results/medqa_B*/metrics.json`, and `docs/04_EVALUATION.md:333-337` lists
"Contamination assertion passed (logged in `metrics.json`)" as a sanity check
before believing any result. CLAUDE.md §2: "Assert this in code ... do not merely
comment it."
**Fix:** have `contamination_assertion` call a real check for MedQA — e.g. max
n-gram overlap of each test question stem against `data/processed/corpus.jsonl`
retrieved chunks — and set `checked`/`applies` from the executed outcome.

### 3.3 — MAJOR · `docs/03_DATASETS.md` (calibration split) vs `configs/base.yaml` (corpus build) vs `data/MANIFEST.json`
`docs/03_DATASETS.md` reserves `pqa_artificial` *only* for fitting calibration
weights; `configs/base.yaml` builds the retrieval corpus from a 20,000-doc

`src/eval/contamination.py` blocklists only `pqa_labeled` test PMIDs and raises
for any other dataset.
**Fix:** before Phase 5, fit calibration on `pqa_labeled` **dev** (not in the
corpus), or extend the blocklist to the exact `pqa_artificial` calibration
items and rebuild the index.

### 3.4 — MAJOR · `configs/agents.yaml` + `configs/base.yaml` (no provenance for most hyper-parameters)
`configs/agents.yaml`: `epsilon`, `evidence_split: [8, 4]`, the budget guards.

## AREA 4 — BASELINE FAIRNESS

### 4.1 — MAJOR · `src/eval/baselines.py` (`_VERIFY_PROMPT`) — single-phrasing strawman risk
The B3 verifier prompt has one phrasing ("Say SUPPORTED only if the evidence
positively supports it, otherwise NOT_SUPPORTED"). The resulting
`verifier_decision_rate = 0.05` is the project's designated motivating result
(`NEXT_SESSION.md:29-32`; `docs/04_EVALUATION.md:264-270` calls it "direct
empirical evidence for the binary bottleneck C2 targets"). There is no
prompt-sensitivity check and no alternative phrasing, while B2 gets a neutral
instruction. As written this is vulnerable to a "strawman by prompt
construction" objection.
**Fix:** run B3 with at least two more verifier phrasings (one neutral, one
permissive) on the dev-20 and report `verifier_decision_rate` for all three
before the claim is used in the paper.

### 4.2 — MAJOR · `results/medqa_B3_d5e3af5_20260906T100551Z/metrics.json` vs `..._20260906T102134Z/metrics.json`
The two committed B3 runs disagree on the statistic the claim rests on:
- `100551Z`: `n_supported_distribution = {"0": 7, "1": 1, "3": 2, "4": 10}` —
  **10/20 questions had all four options SUPPORTED**, accuracy 0.15, 12/20
  `parse_error`, 283 invalid citations.
- `102134Z`: `n_supported_distribution = {"0": 15, "1": 1, "2": 4}`, accuracy
  0.65, 20/20 ok.
Same prompt, same model, same seed; the only difference is `num_ctx`
4096 → 8192. `docs/04_EVALUATION.md:266` quotes only the second distribution and
never notes that it flips to the opposite failure mode under a context-window
change alone.
**Fix:** report both distributions in §5.4 and downgrade the C2 motivating claim
to "unstable at n=20; to be re-measured at scale (Phase 7)" until the
Gemini-tier robustness check runs.

### 4.3 — MAJOR · `src/pipeline.py:190-209` (B2/B3 budget) vs `configs/agents.yaml` (`max_evidence: 12`, `evidence_split: [8,4]`)
B2/B3 receive up to 12 reranked passages **plus** all cached KG triples (up to
40) ≈ up to 52 evidence items. V4 receives `max_evidence: 12` (8 passages + 4
triples). `docs/04_EVALUATION.md:317-324` (Finding 3) then reports
`rank-1-by-support = 0.35` "vs B2's 0.65 ... on the same slice" and attributes
the whole gap to the absence of calibration, with the budget asymmetry unstated.
**Fix:** state the budget asymmetry (12 vs up to ~52 items) at
`docs/04_EVALUATION.md:319`, and add an equal-budget B2 (12-item trimmed bundle)
as the correct comparator before Phase 5 reads that gap.

### 4.4 — MINOR · `configs/` (no per-variant configs)
B0–B3 are code-level branches with no config files (ADR-020); `configs/` holds
only `base.yaml` and `agents.yaml`. There are no V0–V5 configs and no Phase 7
grid configs. `docs/04` §5.4 rows cannot be regenerated from a config path, and
`results/<run_id>/config.yaml` alone does not determine the variant.
**Fix:** add `configs/B0.yaml`..`B3.yaml` (or a `variant:` key in the resolved
config) so the run directory is self-describing.

### 4.5 — MINOR · `src/llm/client.py` (`StatsTracker`) / `src/eval/results.py:97-107`
No per-call model id is recorded — only counts and the static `fallback_chain`.
`docs/00_RESEARCH_SPEC.md:73` requires "pin model ids and record them in every
`config.yaml`". If a `GROQ_API_KEY` were present, some calls would silently route
to a different model with nothing in `metrics.json` showing it.
**Fix:** accumulate `models_used: {model: n_calls}` in the call-stats object and
write it into `metrics.json`.

### 4.6 — MINOR · `src/eval/baselines.py` (B3 fallback path) / `docs/04_EVALUATION.md:267`
